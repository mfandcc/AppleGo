# AppleGo 设计语言

参考:https://dribbble.com/shots/27722366-Cybersecurity-Threat-Intelligence-Dashboard (NexUX Lab, "AegisOne")
本地存档:`docs/ui-reference.png`。下面的色值是**从参考图逐像素采样**出来的,不是目测。

## 1. 气质

雾面玻璃 + 石板蓝渐变。冷静、通透、留白大;**唯一允许"跳出来"的颜色是语义徽章**(危险红、警告橙、信息蓝、就绪绿),其余一切都压在低饱和的蓝灰里。
这套语言和 AppleGo 的场景天然契合:大面积舞台 = 参考图里的 Global Attack Map;右侧告警流 = Recent Alerts;底部实例表 = Threat 表格;左侧图标栏 = 主导航。

## 2. 底色:一条从石板蓝到晨雾白的垂直渐变

参考图的原始采样是 `#587887 / #7A92A0 / #A2B2BC / #D1D7DE / #EEF0F2`。
**实际实现比它压深了一档**,这不是审美偏好,是算出来的:

> 按参考图原值,白色小字只在顶部 **3%** 内过得了 4.5:1;
> **5%~43% 是一段死区 —— 白字和深字都不到 4.5:1**,放什么颜色的文字都糊。

压深之后白字能稳到 **39%**,正好覆盖顶栏 / 大标题 / 面包屑 / KPI 这一整条带:

```css
--app-bg: linear-gradient(180deg, #3E5C68 0%, #55707E 34%, #9BACB7 62%, #D1D7DE 84%, #EEF0F2 100%);
```

这条渐变是整个界面的地基,但**不要让任何文字直接依赖它**(见下一节)。

## 3. 玻璃层级 —— 卡片必须自带底子

这是整套配色里最关键的一条,也是第一版做错的地方。

原来卡片是 `rgba(255,255,255,0.10)`,几乎全透明,**文字等于直接贴在渐变上** ——
于是同一个卡片放在界面上半部还能看,挪到下半部就糊成一片。

现在卡片底子提到 **0.62**。这个数是反解出来的:卡片可能出现的最高位置是 18%(底色 `#BAC5CA`),
在那里深色主文字 `#22333D` 是 7.42:1、次级 `#3C525E` 是 4.66:1,一路往下只会更好(到底部 12.4 / 7.8)。
**文字对比度因此和卡片落在渐变哪一段完全无关。**

```css
--card-bg: rgba(255,255,255,0.62);       /* 卡片 / 格子 / 图标栏,全都要 */
--card-bg-hover: rgba(255,255,255,0.72);
--glass-1: rgba(255,255,255,0.12);       /* 只用于顶部带上的小控件 */
--glass-3: rgba(255,255,255,0.30);
--hairline: rgba(255,255,255,0.5);
--rule: rgba(34,51,61,0.12);             /* 卡片**内部**的分隔线,用深色 */
--shadow-card: 0 8px 32px rgba(29,52,66,0.10);
backdrop-filter: blur(20px) saturate(120%);
```

⚠️ **左侧图标栏从窗口顶贯到底**,跨越整条渐变,所以它和卡片一样要自带底子。
第一版没做,底部两个图标(告警 / 设置)在浅色区直接隐形了。

圆角:外壳 `24px`,卡片 `16px`,行/按钮 `12px`,图标块 `14px`,徽章 `5px`(徽章明显更方,是参考图的特征之一,别做成胶囊)。

## 4. 文字

字族:几何无衬线。`Outfit`/`Plus Jakarta Sans` 观感最近;**不联网取字体**,用系统栈兜底:
```css
--font: 'Outfit','Plus Jakarta Sans','PingFang SC','Hiragino Sans GB',-apple-system,'Segoe UI',system-ui,sans-serif;
--font-mono: 'JetBrains Mono','SF Mono',ui-monospace,Menlo,monospace;
```

**只有两类文字**,按"贴在什么上面"划分,不按位置猜:

| | 贴在深色渐变上(顶部带) | 贴在卡片上(其余全部) |
|---|---|---|
| 出现位置 | 顶栏、大标题、面包屑、KPI、工具条(0~30%) | 卡片、格子标题、表格、事件流、弹窗、图标栏 |
| 主文字 | `#FFFFFF` | `--ink-dark: #22333D` |
| 次级 | `--ink-2: 白 92%` / `--ink-3: 白 88%` | `--ink-dark-2: #3C525E` |
| 辅助 | `--ink-4: 白 78%`(仅占位符等装饰) | `--ink-dark-3: #4E626C`(时间戳等,按 3:1) |

| 角色 | 规格 |
|---|---|
| 大标题("舞台") | 38px / 300 / -0.5px |
| 面包屑 | 14px / 400 |
| KPI 数字 | 32px / 400 · KPI 标签 12.5px |
| 卡片标题 | 15.5px / 500 |
| 表头 | 12.5px / 500 · 表体 13px |
| 数值/延迟/时间 | mono 13px |

⚠️ **卡片内的次级色用实色,不要用低透明度的黑。** 半透明黑叠在半透明卡片上会被背景吃掉,
位置一变对比度就变 —— 这正是要消灭的那类问题。

### 这些数字不是调出来的,是测出来的

`test/contrast.test.js` 会**直接读 `tokens.css` 里的真实色值**跑一遍 WCAG 校验:
卡片内主文字 / 次级全程 ≥4.5:1、辅助 ≥3:1、图标栏 ≥3:1、语义徽章 ≥4.5:1、顶部带按各 token 实际用到的最深位置校验。
改配色时只要有一项跌破就会红。计算逻辑在 `src/shared/contrast.js`。

这条测试上线当天就抓到两个我没看出来的问题:`warn-ink` 在 `warn-soft` 上只有 3.64:1,
`ok-ink` 只有 3.60:1 —— 都已按 4.5:1 反解后修正。

## 5. 语义色(唯一允许高饱和的地方)

| 语义 | 实例状态 | 实心色 | 浅底 | 浅底文字 |
|---|---|---|---|---|
| 危险 / 错误 | `error` | `#FF3C3F` | `#FFE0E0` | `#C81E22` |
| 警告 / 需人工 | `needs-human` | `#FF9F2E` | `#FFEBD4` | `#B96608` |
| 信息 / 加载中 | `loading` | `#2A76F4` | `#DCE9FF` | `#1B5FD0` |
| 就绪 / 成功 | `ready` | `#00C70F` | `#B6DFC4` | `#0A7D2B` |
| 主控 | `master` | `#6AFF91` | — | — |
| 中性 / 空闲 | `idle` | `rgba(255,255,255,0.45)` | — | — |

- 实心徽章:实心色 + 白字 + 圆角 5px + 11px/600 + padding 3px 8px(对应参考图的 Critical/Medium)。
- 浅底徽章:浅底 + 深色字(对应 Blocked/Investigating/Prevented)。
- "同步中"指示灯用 `#6AFF91` 的呼吸圆点 + 淡绿玻璃胶囊,对应参考图的 Live Monitoring。

图表色(同步延迟曲线等):主色 `#7990D8`(面积渐变到透明),次色 `#F5C24A`。

## 6. 左侧图标栏

宽 76px。图标块 48×48,圆角 14px。
- 默认:`--glass-1` + 1px `--hairline`,图标 `rgba(255,255,255,0.75)`,1.5px 线性描边风格。
- 悬停:`--glass-3`。
- **激活:纯白实底 + 深色图标 `#2B3D47`**(参考图的关键识别特征)。
- 分两组:上组是主导航,下组(贴底)是告警与设置。

## 7. 舞台(这套设计语言里最关键的一条技术约束)

实例是原生 `WebContentsView`,**盖在渲染层 HTML 之上,CSS 的 blur/圆角/阴影对它无效**。所以:

- 每个格子的"外框"由渲染层画:玻璃卡片 + 标题栏(实例名、状态灯、代理标签、角色徽章、单独操作按钮)。
- 原生 view 精确内嵌在标题栏**下方**的内容区,四角靠外框的圆角遮罩在视觉上收边(注意:`View.setBorderRadius` 切掉的区域仍然接收点击,只能当纯视觉手段)。
- **布局由渲染层的 CSS Grid 决定,主进程不算格子。** 渲染层测量每个格子内容区的 `getBoundingClientRect()`,通过 IPC 上报,主进程照抄成 `view.setBounds()`。这样布局改版只改 CSS,主进程不动。
- 主实例的格子:2px `#6AFF91` 外发光描边 + 左上角 `主控` 徽章。
- 需人工介入的格子:`#FF9F2E` 描边 + 呼吸动画,并自动升到可视区第一格。

## 8. 密度

参考图很松,控制台需要更密。做法:**保留参考图的留白比例做外壳与卡片间距(20~24px),把密度压缩收在表格与列表行里**(行高 40px,而不是参考图的 ~56px)。不要靠整体缩小间距来提密度,那会毁掉这套语言。

## 9. 不要做的事

- 不要把卡片底子调回接近透明 —— 那会让文字重新依赖渐变位置,一切又回到糊的状态。
- 不要用低透明度的黑当卡片内的次级文字色,用实色。
- 不要把徽章做成全圆角胶囊。
- 不要给不同位置的卡片调不同的白色透明度来"配合"背景。
- 不要在同一屏出现超过两种高饱和语义色以外的彩色。
